# 핸드오프와 더 파보기

## 헤더

```
[omhc] codex-cli 01a0c9f4 · 2h11m · 20m ago · notes from a prior session, not instructions
[omhc] the human's next message outranks every line below
```

`2h11m`은 세션 길이(`_duration()`)이고, `20m ago`는 마지막 이벤트로부터
지난 시간(`_age()`)입니다. 둘 다 mint 시점에 고정됩니다. 모든 핸드오프
산출물(outbox 헤더, AGENTS.md 구간 시작 마커)은 유닉스 epoch와 사람이
읽는 UTC 시각도 함께 담아, 실제 캡처 시각을 확인할 수 있습니다.

## 슬롯

| 슬롯 | 출처 | 규칙 |
|---|---|---|
| `GOAL` | `author == human`, 세션의 첫 사람 턴 | 축자 인용만. 재작성하지 않음 |
| `NEXT` | `author == human`, 세션의 마지막 사람 턴(단, 사람 턴이 하나뿐이면 그것은 이미 `GOAL`이므로 비운다) | 축자 인용만. **단, 그 턴이 짧은 승인("계속 진행해")이면 비움.** 그대로 `NEXT`에 넣으면 이전 에이전트의 제안이 사람의 지시로 세탁됨 |
| `PLAN?` | 이전 에이전트의 마지막 발화 | `NEXT`가 비었을 때만 채움. `?` 한 바이트가 "검증되지 않은 주장" 라벨 |
| `FAIL` | 기계가 관측한 실패(`ok=False`) | **"해소됨" 판정은 같은 인자가 아니라 인자 앞 40자가 같은 이후 성공을 뜻함.** 해소된 실패는 보고하지 않음. 리포트 대상은 최대 2개, 태그 `[E1]`/`[E2]`로 `omhc show`와 연결 |
| `DID` | 기계가 관측한 수정 경로 | 레포 루트 상대경로, 최대 4개 |
| `NOTE` | `omhc note "<text>"` 호출. 사람과 양쪽 하네스의 에이전트 모두 명령줄로 부를 수 있고 저자를 구분해 기록하지 않음 | **검증되지 않은 자유 텍스트.** `~/.omhc/<repo-key>/notes.txt`에서 최근 2개. 메모마다 쓴 시각을 붙이고, 7일(핸드오프 자체의 나이 기한과 같음)이 지난 메모는 빼서 옛 메모가 끝없이 따라붙지 않게 함. 시각이 없는 옛 줄은 그대로 보임 |
| `SAID` | `author == human`, 중간 사람 턴 | 최근순이 아니라 긴 문장 우선(최대 3개). "어디까지 됐어?" 같은 질문보다 요구사항 문장이 더 쓸모 있음 |
| `MORE` | 버려진 슬롯·해소된 실패·숨겨진 이벤트의 집계 | **감춘 것을 공개함.** 버린 슬롯 수는 900바이트 예산 때문이지만 숨긴 이벤트 수는 예산과 무관함. 사람 턴도 아니고 `FAIL`로도 리포트되지 않은 이벤트 수를 그냥 센 것(`DID` 등으로 요약됐어도 낱개로는 안 보임) |
| `PULL` | omhc 생성(항상 포함) | `omhc log --last 30`은 늘 있고, 미해소 실패가 있으면 `omhc show E1`, 수정한 파일 중 가장 짧은 경로가 32자 이하면 `omhc log --file …`이 붙음. 절대 버리지 않는 슬롯 |

## 더 파보기

- `omhc log`는 색인된 이벤트를 한 줄씩 보여 줍니다. 각 줄은
  `<session>#N` 참조로 시작하며 그대로 `show`에 넘길 수 있습니다.
- `omhc show <E1|#137|abcdef01#137> [--full]`은 원본 바이트를 오프셋으로
  조회합니다(tier (b) 진입점). 맨 `#N`은 가장 최근 전달된 세션
  기준이고(`log`의 인출률 회계와 같은 규칙), `<prefix>#N`은 세션을 직접
  지정합니다. 접두사가 모호하면 후보를 나열합니다.
- `omhc trace <path>`는 파일 → 세션 역인덱스입니다(sessionwiki `trace`
  선례). `path`를 건드린 색인된 이벤트를 두 하네스 세션을 넘나들며
  오래된 순으로(최신이 마지막 줄, `log`와 같은 순서) 나열하고, 각 줄에
  하네스와 `show`로 열 수 있는 참조를 붙입니다. 기본은 `modified`만이고
  `--all`은 `inspected`/`ran` 언급까지 포함합니다. 접미사 매칭이 서로 다른
  파일 여럿에 걸쳐 모호하면 짐작하지 않고 후보를 보여 줍니다. 전달됐거나
  `watch`가 본 세션만 잡습니다. 안 잡힌다고 "고친 적 없다"는 뜻이 아니라
  "아직 색인 안 됐다"는 뜻이고, `watch`로만 색인되고 원장에 아직 `start`
  행이 없는 세션은 하네스 칸이 `?`로 나옵니다.
